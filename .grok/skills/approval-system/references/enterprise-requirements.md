# 企業線上簽核系統 — 需求問卷紀錄

日期：2026-07-24  
用途：驅動 `approval-system` skill 與後續功能優先序  

## 問卷與答案

### 1. 使用族群規模與組織型態

**答：小型（約 30 人內）**

- 部門數有限，但流程能力仍需「完整」而非精簡版  
- 避免過度企業級複雜 UI，但後端能力要夠  

### 2. 最核心、使用最頻繁的申請類型（多選）

**答：全部勾選**

- 請假／出差／加班  
- 請購／費用報支  
- 一般簽呈／公文  
- IT／報修／權限申請  
- 其他（之後補充）  

→ 表單引擎與種子流程需涵蓋上述類型，並可擴充「其他」。

### 3. 簽核關卡常見模式（多選）

**答：全部勾選**

- 固定層級（申請人→主管→副總→總經理）  
- 依金額／條件分岔  
- 會簽（多人皆需同意）  
- 擇一簽（任一人即可）  
- 可加簽／改派／代理  

→ 流程引擎是核心競爭力，不可只做直線簽核。

### 4. 通知管道（多選）

**答：全部勾選**

- Email  
- LINE  
- 瀏覽器桌面通知／彈窗  
- 系統內待辦  

→ 多通道；待辦是底線，外推（Email/LINE/桌面）提升不漏單。

### 5. 行動裝置

**答：手機只收通知，回公司再簽**

- 優先：LINE／Email 可讀、可點連結（內網連結在外可能打不開 → 文案需說明）  
- 次要：完整手機簽核 UI（非近程第一優先）  

### 6. 權限與角色（多選）

**答：全部勾選**

- 一般員工／部門主管／高階主管  
- 人資專用（假單報表等）  
- 財務／採購專用  
- IT／系統管理員  
- 需細到功能權限勾選  

→ 維持/強化 `permissions` 模型。

### 7. 文件與合規（多選）

**答：全部勾選**

- PDF 歸檔＋下載  
- PDF 數位簽章  
- 不可刪除／完整稽核軌跡  
- 保存年限／不可竄改  
- 匯出 Excel 報表  

→ 刪除策略宜嚴；稽核 log 必留；報表持續強化。

### 8. 系統整合優先（多選）

**答：**

- LINE 通知  
- 郵件伺服器（MailPlus／iCloud）  
- ERP／出勤／會計（中長期）  

未列為本階段：AD／LDAP、完全獨立不整合。

### 9. 部署與存取

**答：僅公司內網**

- NAS 區網為準  
- 不預設埠轉發到公網  
- 外網需求應走 VPN 或另案 HTTPS  

### 10. 近 3–6 個月第一優先

**答：通知可靠（LINE／Email／桌面）**

落地檢查清單：

- [x] Email SMTP 執行期設定（一鍵包不含設定檔）  
- [x] 桌面 Notification + 中央彈窗（待簽核）  
- [x] LINE 服務（`D:\Line 專案`）與簽核呼叫串接（`server/line-notify.js`）  
- [x] 系統設定：如何啟用 LINE、誰可設定（builtin_admin / any_admin / permission）  
- [ ] 通知失敗可觀測（log／重試／管理員可見 UI）  
- [x] 成員 LINE 綁定（Line 專案 Webhook）+ 設定頁可查綁定名單  

## 衍生原則

1. **通知 > 華麗手機版**（符合 Q5＋Q10）  
2. **流程能力完整** 即使人數少（Q3）  
3. **內網優先** 的安全與 baseUrl 文案（Q9）  
4. **密鑰不進安裝包**（Email／LINE）  
5. **GitHub 每次功能變更要更新**（使用者要求）
